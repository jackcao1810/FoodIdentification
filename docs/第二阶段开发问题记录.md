#### 问题23：集成 HuggingFace nateraw/food 菜品识别模型

**功能描述：**
使用 HuggingFace 的 nateraw/food 模型进行菜品识别，该模型在 Food-101 数据集上训练，准确率达到 89.13%。

**技术实现：**
使用 Transformers.js 库在浏览器中运行模型推理

**修改文件：**
- `client/src/services/foodRecognitionService.ts`
- `client/package.json` (添加 @xenova/transformers 依赖)

**关键代码：**
```typescript
import { env, pipeline, type Pipeline } from '@xenova/transformers';

env.allowLocalModels = false;
env.useBrowserCache = true;

class FoodRecognitionService {
  private classifier: Pipeline | null = null;

  async loadModel(): Promise<void> {
    this.classifier = await pipeline('image-classification', 'nateraw/food', {
      quantized: true,
      progress_callback: (progress) => {
        if (progress.status === 'progress') {
          const percent = Math.round(progress.progress || 0);
          this.updateProgress(10 + percent * 0.6, '正在下载模型...');
        }
      }
    });
  }

  async recognize(imageElement: HTMLImageElement | HTMLCanvasElement): Promise<FoodRecognitionResult> {
    const result = await this.classifier!(imageElement as HTMLImageElement, {
      topk: 5
    }) as any[][];
    return this.processModelResults(result);
  }
}
```

**验证结果：** ✅
- 模型成功从 HuggingFace 加载
- 支持进度显示（下载进度、识别进度）
- 菜品识别准确率达到预期

#### 问题24：用户交互式分量调整估算重量和营养

**功能描述：**
通过滑块让用户调整每道菜的分量，实时计算重量、热量和营养成分。

**技术实现：**
1. 增强 PortionSelector 组件，传递实际营养数据
2. 实时计算分量对应的营养成分
3. 根据密度估算体积（ml）

**修改文件：**
- `client/src/components/common/PortionSelector.tsx`
- `client/src/pages/ResultEnhanced.tsx`

**关键改进：**
```typescript
// PortionSelector.tsx
interface PortionSelectorProps {
  caloriesPer100g: number;
  proteinPer100g: number;  // 新增
  carbsPer100g: number;    // 新增
  fatPer100g: number;      // 新增
  density?: number;        // 新增
  standardPortion?: number;
  onChange: (portionInGrams: number, nutrients: {...}) => void;
}

// 营养计算使用实际数据
const calculateNutrients = useCallback((grams: number) => {
  const multiplier = grams / 100;
  return {
    calories: Math.round(caloriesPer100g * multiplier),
    protein: parseFloat((proteinPer100g * multiplier).toFixed(1)),
    carbohydrates: parseFloat((carbsPer100g * multiplier).toFixed(1)),
    fat: parseFloat((fatPer100g * multiplier).toFixed(1))
  };
}, [caloriesPer100g, proteinPer100g, carbsPer100g, fatPer100g]);
```

**UI 特性：**
- 滑块调整分量（20g-600g）
- 分量标签（小份/偏少/适中/偏多/大份）
- 估算体积（ml）
- 实时显示每项营养成分和每百克参考值
- 手动输入分量

**验证结果：** ✅
- 滑块可以调整分量
- 实时计算热量和营养
- 总计面板正确更新

#### 问题4：sql.js缺少类型声明文件

**问题描述：**
```
Could not find a declaration file for module 'sql.js'.
'node_modules/sql.js/dist/sql-wasm.js' implicitly has an 'any' type.
```

**问题分析：**
- sql.js是JavaScript库，没有内置TypeScript类型声明
- 项目使用严格模式，隐式any类型导致编译失败
- 需要创建自定义类型声明文件

**解决方案：**
创建sql.js类型声明文件

**创建文件：** `server/src/types/sql.js.d.ts`

```typescript
declare module 'sql.js' {
  export interface Database {
    run(sql: string, params?: any[]): void;
    exec(sql: string, params?: any[]): Array<{ columns: string[]; values: any[][] }> | undefined;
    prepare(sql: string): Statement;
    export(): Uint8Array;
    close(): void;
  }

  export interface Statement {
    run(params?: any[]): void;
    get(params?: any[]): any[] | undefined;
    all(params?: any[]): any[];
    bind(params?: any[]): boolean;
    reset(): void;
    free(): void;
  }

  export interface Config {
    locateFile?: (file: string) => string;
  }

  export default function initSqlJs(config?: Config): Promise<{ Database: typeof Database; locateFile: (file: string) => string }>;
}
```

**验证结果：** ✅ sql.js类型错误消失

#### 问题11：登录后刷新页面用户名消失

**问题描述：**
用户登录后刷新页面，右上角显示的用户名消失，页面状态变为未登录状态。

**问题分析：**
- `authSlice.ts` 的 `initialState` 只从 localStorage 恢复了 token
- 但 `initialState.user` 始终为 `null`
- 页面刷新后 Redux store 被重置，虽然 token 恢复了，但 user 信息丢失

**解决方案：**
1. 添加 `getStoredUser` 函数从 localStorage 恢复用户信息

**修改文件：** `client/src/store/slices/authSlice.ts`

```typescript
const getStoredUser = (): User | null => {
  try {
    const userStr = localStorage.getItem('user');
    return userStr ? JSON.parse(userStr) : null;
  } catch {
    return null;
  }
};

const initialState: AuthState = {
  user: getStoredUser(),  // 从 localStorage 恢复
  token: localStorage.getItem('token'),
  isAuthenticated: !!localStorage.getItem('token'),
  loading: false,
  error: null,
};
```

2. 登录时将用户信息存储到 localStorage

```typescript
setCredentials: (state, action: PayloadAction<{ user: User; token: string }>) => {
  state.user = action.payload.user;
  state.token = action.payload.token;
  state.isAuthenticated = true;
  localStorage.setItem('token', action.payload.token);
  localStorage.setItem('user', JSON.stringify(action.payload.user));  // 新增
},
```

3. 退出登录时清除用户信息

```typescript
logout: (state) => {
  state.user = null;
  state.token = null;
  state.isAuthenticated = false;
  localStorage.removeItem('token');
  localStorage.removeItem('user');  // 新增
},
```

**验证结果：** ✅ 刷新页面后用户名保持显示

```typescript
    // 查询更新后的用户数据并返回
    const result = db.exec(
      'SELECT id, username, email, height_cm, weight_kg, target_calories, target_protein, target_carbohydrates, target_fat FROM users WHERE id = ?',
      [req.user!.id]
    );

    if (result.length === 0 || result[0].values.length === 0) {
      throw new AppError('用户不存在', 404);
    }

    const columns = result[0].columns;
    const userRow = result[0].values[0];
    const user: any = {};
    columns.forEach((col, i) => { user[col] = userRow[i]; });

    res.json({
      success: true,
      data: {
        id: user.id,
        username: user.username,
        email: user.email,
        heightCm: user.height_cm,
        weightKg: user.weight_kg,
        targetCalories: user.target_calories,
        targetProtein: user.target_protein || 80,
        targetCarbohydrates: user.target_carbohydrates || 300,
        targetFat: user.target_fat || 65,
      },
    });
  } catch (error) {
    next(error);
  }
});
```

**验证结果：** ✅
- 编辑用户名后保存，个人中心正确显示修改后的用户名
- 右上角"你好，{用户名}"正确显示修改后的用户名
- localStorage 中的用户数据同步更新
- 刷新页面后用户名保持显示

#### 问题21：拍照上传提示无法访问摄像头

**问题描述：**
点击"拍照上传"按钮启动摄像头后，界面显示"正在启动摄像头..."，但很快变成"无法访问摄像头，请确保已授予摄像头权限"的错误提示，而实际上摄像头已经启动。

**问题分析：**
- React StrictMode 会在开发模式下双重渲染组件，导致 useEffect 被调用两次
- 每次 useEffect 调用都会尝试启动摄像头
- `getUserMedia` 在短时间内被多次调用可能触发浏览器的限制
- `startCamera` 函数的检查逻辑存在时序问题

**问题定位：**
```typescript
// 之前的实现
useEffect(() => {
  startCamera();
  return () => {
    if (stream) {
      stream.getTracks().forEach((track) => track.stop());
    }
  };
}, []);
```

**解决方案：**

使用 ref 跟踪摄像头启动状态，防止重复启动和误判

**修改文件：** `client/src/components/upload/CameraCapture/CameraCapture.tsx`

```typescript
// 修改前
const CameraCapture: React.FC<CameraCaptureProps> = ({
  onCapture,
  onClose,
  facingMode = 'environment',
}) => {
  const [stream, setStream] = useState<MediaStream | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);
  const videoRef = useRef<HTMLVideoElement>(null);

  const startCamera = useCallback(async () => {
    if (stream) return;
    setIsLoading(true);
    setError(null);
    try {
      const mediaStream = await navigator.mediaDevices.getUserMedia({ video: { facingMode } });
      setStream(mediaStream);
      if (videoRef.current) {
        videoRef.current.srcObject = mediaStream;
        await videoRef.current.play();
      }
    } catch (err) {
      setError('无法访问摄像头，请确保已授予摄像头权限');
    } finally {
      setIsLoading(false);
    }
  }, [facingMode]);

  useEffect(() => {
    startCamera();
    return () => {
      if (stream) {
        stream.getTracks().forEach((track) => track.stop());
      }
    };
  }, [startCamera]);
};

// 修改后
const CameraCapture: React.FC<CameraCaptureProps> = memo(({
  onCapture,
  onClose,
  facingMode = 'environment',
}) => {
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);
  const videoRef = useRef<HTMLVideoElement>(null);
  const streamRef = useRef<MediaStream | null>(null);
  const startingRef = useRef(false);
  const isMountedRef = useRef(true);

  const startCamera = useCallback(async () => {
    if (startingRef.current) return;
    if (streamRef.current) return;
    
    startingRef.current = true;
    setIsLoading(true);
    setError(null);

    try {
      const constraints: MediaStreamConstraints = {
        video: {
          facingMode: facingMode,
          width: { ideal: 1920 },
          height: { ideal: 1080 },
        },
      };

      const mediaStream = await navigator.mediaDevices.getUserMedia(constraints);
      streamRef.current = mediaStream;

      if (videoRef.current && isMountedRef.current) {
        videoRef.current.srcObject = mediaStream;
        await videoRef.current.play();
        setIsLoading(false);
      } else {
        mediaStream.getTracks().forEach((track) => track.stop());
        streamRef.current = null;
      }
    } catch (err) {
      console.error('摄像头访问失败:', err);
      setError('无法访问摄像头，请确保已授予摄像头权限');
      streamRef.current = null;
    } finally {
      startingRef.current = false;
      if (isMountedRef.current) {
        setIsLoading(false);
      }
    }
  }, [facingMode]);

  useEffect(() => {
    isMountedRef.current = true;
    startCamera();

    return () => {
      isMountedRef.current = false;
      if (streamRef.current) {
        streamRef.current.getTracks().forEach((track) => track.stop());
        streamRef.current = null;
      }
    };
  }, [startCamera]);
});
```

**验证结果：** ✅
- 点击"拍照上传"后，摄像头正确启动
- 不再显示"无法访问摄像头"的错误提示
- 摄像头视频流正常显示

#### 问题22：退出摄像头页面后摄像头未关闭

**问题描述：**
点击关闭按钮退出摄像头页面后，摄像头指示灯仍然亮着，说明摄像头仍在运行，没有被正确关闭。

**问题分析：**
- useEffect 的 cleanup 函数依赖于 `stream` 状态变量
- 状态更新是异步的，组件卸载时 `stream` 状态可能还未更新
- 导致 cleanup 函数中的停止逻辑无法正确获取到媒体流引用

**解决方案：**

使用 ref 保存媒体流引用，确保 cleanup 时能够正确停止摄像头

**修改文件：** `client/src/components/upload/CameraCapture/CameraCapture.tsx`

```typescript
// 关键修改：使用 streamRef 而非 stream 状态
useEffect(() => {
  isMountedRef.current = true;
  startCamera();

  return () => {
    isMountedRef.current = false;
    if (streamRef.current) {  // 使用 ref 而非 state
      streamRef.current.getTracks().forEach((track) => track.stop());
      streamRef.current = null;
    }
  };
}, [startCamera]);

const handleSwitchCamera = useCallback(() => {
  if (streamRef.current) {  // 使用 ref
    streamRef.current.getTracks().forEach((track) => track.stop());
    streamRef.current = null;
  }
  setIsFrontCamera((prev) => !prev);
  startingRef.current = false;
}, []);
```

**验证结果：** ✅
- 退出摄像头页面后，摄像头正确关闭
- 摄像头指示灯熄灭
- 重新进入摄像头页面可以正常启动

### 1. Heroicons图标版本迁移注意事项

**问题：** 从Heroicons v1迁移到v2时，图标名称发生变化

**常见映射：**
| 旧名称 | 新名称 |
|--------|--------|
| Upload | ArrowUpTrayIcon |
| X | XMarkIcon |
| Camera | CameraIcon |
| Image | PhotoIcon |
| Loader | ArrowPathIcon |

**最佳实践：**
- 查阅官方文档确认图标名称
- 使用命名导入避免命名冲突
- 保持图标库版本一致

---

### 2. 第三方库类型声明管理

**问题：** 纯JavaScript库可能缺少TypeScript类型声明

**解决方案：**
1. 检查是否有@types包：npm i --save-dev @types/library-name
2. 创建自定义.d.ts声明文件
3. 使用skipLibCheck跳过库检查（不推荐）

**sql.js示例：**
```typescript
// server/src/types/sql.js.d.ts
declare module 'sql.js' {
  export interface Database {
    run(sql: string, params?: any[]): void;
    exec(sql: string, params?: any[]): Array<{ columns: string[]; values: any[][] }> | undefined;
    // ... 其他方法
  }
  export default function initSqlJs(config?: Config): Promise<{ Database: typeof Database }>;
}
```

---

### 3. Express Request类型扩展

**问题：** 中间件添加的属性在类型中不可见

**解决方案：**
创建类型扩展文件

**示例：**
```typescript
// server/src/types/express.d.ts
import { Request } from 'express';

declare global {
  namespace Express {
    interface Request {
      user?: {
        id: number;
        email: string;
        username: string;
      };
    }
  }
}
```

**注意：** 文件必须包含import或export语句才能被TypeScript识别为模块

---

### 4. jsonwebtoken类型签名问题

**问题：** jwt.sign的expiresIn参数类型严格

**错误用法：**
```typescript
// ❌ 可能失败：环境变量可能是undefined
{ expiresIn: process.env.JWT_EXPIRES_IN || '7d' }
```

**正确用法：**
```typescript
// ✅ 编译时确定字符串
{ expiresIn: '7d' }

// 或
const expiresIn = '7d';
{ expiresIn }
```

---

### 5. 遗留文件清理

**问题：** 依赖变更后遗留的文件可能导致编译错误

**解决方案：**
- 定期检查package.json中的依赖变更
- 删除不再使用的文件
- 使用代码搜索确认文件引用

**本项目案例：**
- better-sqlite3 → sql.js迁移后
- 遗留的init-db.ts仍然导入better-sqlite3
- 删除后问题解决
